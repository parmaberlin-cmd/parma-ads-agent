# Dependency security blocker — updated 2026-09-04

The original `qs@6.15.3` blocker has been remediated safely: `package-lock.json` was regenerated by npm in CI and now resolves `qs@6.16.0`. A clean `npm ci` succeeds with that lockfile.

CI is still intentionally fail-closed because a newly surfaced moderate advisory affects `stream-json<=3.4.0`. The current `google-ads-api@24.1.0` dependency requires `stream-json^1.8.0`, resolving to `1.9.1`, while npm's automatic force fix would downgrade `google-ads-api` to `20.0.0`, which is a breaking change.

## Current remediation state

- `qs`: remediated to `6.16.0` with an npm-generated lockfile.
- `npm ci`: verified successful after lock regeneration.
- `stream-json`: unresolved moderate DoS advisory via `google-ads-api@24.1.0`.
- `google-ads-api@24.1.0`: current latest release at time of verification and still carries the affected transitive range.
- `npm audit fix --force`: rejected because it proposes a breaking downgrade to `google-ads-api@20.0.0`.
- Directly overriding `stream-json` to 3.x is not considered safe without compatibility validation because stream-json 2.x/3.x contain major API changes and 3.x moved to ESM.

## Required remediation

1. Keep the audit threshold unchanged (`npm audit --omit=dev --audit-level=moderate`).
2. Do not force-downgrade `google-ads-api` merely to make CI green.
3. Do not force a `stream-json` major override without a compatibility test proving the Google Ads client path works.
4. Prefer an upstream `google-ads-api` release that moves to a patched compatible stream-json line, or a separately validated replacement/upgrade path.
5. Until then, CI remains red at the dependency audit gate and no production deployment is permitted.

## Safety

Do not weaken or skip the dependency audit. Syntax/tests can be run independently for engineering diagnosis, but they do not override the security gate. This blocker is independent from campaign/tracking/spend permissions.
